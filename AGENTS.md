# Groundrule (open source) — Agent Instructions

Groundrule turns engineering standards into agent context, checks, and evidence.
This repository is the **open-source kernel** (Apache-2.0). The proprietary cloud lives in a separate repo.

Product context: `../Groundrule_Product_Vision.md` and `../Groundrule_Build_Plan.md` (local only, not part of this repo).

## Layout

| Path | Purpose |
|------|---------|
| `packages/spec` | Zod schemas + types for every document kind; generates JSON Schema into `schemas/` |
| `packages/core` | Workspace loading (config, packs, overrides, exceptions), git diff, scope, runner, `Evaluator` interface |
| `packages/evaluators` | Built-in checks: `files`, `regex`, `dependencies`, `change-set`, `semgrep`, `llm` (stub until 0.2) |
| `packages/reporters` | Output: terminal, JSON, SARIF, Markdown |
| `packages/adapters` | Agent instructions: AGENTS.md, CLAUDE.md, Cursor rules, Copilot instructions |
| `packages/packs` | Bundled standard packs in `catalog/` (`groundrule:packs/<name>`) |
| `packages/cli` | The `groundrule` command |
| `action/` | GitHub Action |
| `examples/foundation` | The four foundation standards (Build Plan §4.5). Must always pass end to end |
| `.groundrule/` | Groundrule's own standards (dogfooding) |
| `docs/adr/` | Architecture decision records |
| `rfcs/` | Proposals for spec changes |

Planned: `packages/mcp` (Milestone 2), `evals/` (Milestone 2).

## Commands

```bash
pnpm install
pnpm check        # lint + build + typecheck + test. Must pass before any PR.
node packages/cli/dist/bin.js check --all    # Groundrule on its own repo
node packages/cli/dist/bin.js sync           # after changing .groundrule/
pnpm format       # Biome autofix
pnpm changeset    # required for user-facing changes to published packages
```

## Rules

### Protected areas — human review required
Changes to these need an ADR or RFC and line-by-line human review. Do not change them as a side effect of other work:
- `packages/spec/src/**` (the public document format)
- The `Evaluator` interface in `packages/core/src/evaluator.ts`
- `tsconfig.base.json`, `biome.json`, CI workflows

Spec changes must stay backward compatible within `v1alpha1` unless an RFC says otherwise. Every new field needs a `.describe()` so editors show help text.

### Code
- TypeScript strict, ESM only, Node >= 22. Imports use `.js` extensions.
- No `any`. Validate untrusted input with Zod at boundaries.
- Library code never throws for bad user input; return diagnostics with file, line, column, and path.
- Never write to stdout from library packages. Only the CLI prints.
- Keep dependencies minimal; justify each new one in the PR.

### Tests
- Every change ships with tests (Vitest, files in `test/`).
- Bugs get a regression test first.
- `examples/foundation` must keep passing end to end (`packages/evaluators/test/foundation-gate.test.ts`).

### Output and UX
User-facing output (CLI, PR comments, diagnostics) follows Build Plan §15: precise, calm, never scolding; every finding says what failed, which standard, the evidence, and how to fix it. Label whether a result is deterministic, static analysis, or AI.

### Security
- Never send repository content anywhere except an explicitly configured LLM provider, and redact secrets first.
- Never execute code from the repository under evaluation.

## Engineering standards

These are this repository's engineering ground rules. Follow them in every change.
Before you finish a task, run `npx groundrule check` and fix what it reports.
For the reasoning and examples behind a rule, run `npx groundrule explain <ID>`.

### Everywhere

- **SEC-001** No private keys in the repository · _blocker_
  Never commit private keys. Load them at runtime from a secret manager or the environment.

- **SEC-002** No environment files in the repository · _blocker_
  Do not commit .env files. Commit a .env.example with placeholder values instead.
  - Do: `.env.example with placeholder values`
  - Don't: `.env with real values`

- **SEC-003** No access tokens in code · _blocker_
  Never hard-code cloud keys or API tokens (AWS, GitHub, Slack, Stripe live keys). Read them from the environment or a secret manager.

- **SEC-004** Do not disable TLS verification · _blocker_
  Never disable TLS certificate verification, not even "temporarily" or in scripts. Fix the trust store or certificate instead.
  - Don't: `rejectUnauthorized: false`

- **TS-003** No eval or new Function · _blocker_
  Never use eval() or new Function() in application code. (typescript, javascript)

- **GR-002** Spec changes need an RFC · _warning_
  Changes to packages/spec/src come with an RFC in rfcs/ (new or updated) in the same change.

- **GR-003** Protected interfaces change only with review · _warning_
  Do not change packages/spec/src, the Evaluator interface (packages/core/src/evaluator.ts), tsconfig.base.json, biome.json, or CI workflows as a side effect of other work. Propose the change separately and flag it for human review.

- **SEC-005** Commit a dependency lockfile · _warning_
  Commit the lockfile your package manager produces. (typescript, javascript, python, rust, go)

- **SEC-006** Never log secrets or personal data · _warning_
  Never log secrets, tokens, cookies, full request/response bodies, or personal data. Log IDs and outcomes, and redact before logging.

- **TS-001** No console.log in application code · _warning_
  Use the project's logger instead of console.log or console.debug in application code. Tests, scripts, and CLIs may print. (typescript, javascript)
  - Do: `logger.info({ orderId }, "order created")`
  - Don't: `console.log(order)`

- **TS-002** No deprecated HTTP and UUID packages · _warning_
  Do not add request, request-promise, or node-uuid. Use fetch (built into Node 18+) and crypto.randomUUID() instead. (typescript, javascript)

- **TS-005** Type and validate at the boundaries · _warning_
  Avoid any. Validate untrusted input at the boundary with the project's schema library (e.g. zod) and use the inferred types. Reuse existing types and helpers before adding new ones. (typescript)

- **TS-004** Prefer @ts-expect-error over @ts-ignore · _advisory_
  Use // @ts-expect-error with a reason instead of // @ts-ignore. (typescript)

### `packages/*/src/**` (except `packages/cli/src/**`)

- **GR-001** Library packages never print · _blocker_
  Library packages never write to stdout or stderr. Return data and diagnostics; the CLI prints.
