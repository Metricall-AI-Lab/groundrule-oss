# ADR 0004: Kubernetes-style versioned documents, strict schemas

- **Status:** Accepted
- **Date:** 2026-10-07

## Context
The format will be written by hand, generated by tools, and read by editors and other vendors. It must evolve without breaking users and catch authoring mistakes early.

## Decision
Every document has `apiVersion: groundrule.dev/v1alpha1` and a `kind` (`Standard`, `Pack`, `Config`, `ExceptionList`). Schemas are defined once in Zod and exported as JSON Schema. Objects are strict: unknown keys are errors (so `severty:` is caught), except check options, which belong to evaluators. Diagnostics point to file, line, column, and field.

## Consequences
- Editors get autocomplete and validation from the JSON Schemas.
- Breaking changes require a new `apiVersion` and an RFC; a `groundrule migrate` command will convert documents.
- Strictness may annoy authors adding custom metadata; `metadata.labels` is the escape hatch.
